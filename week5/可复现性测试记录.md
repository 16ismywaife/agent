## 测试 1 · 换 Python 解释器（验"零依赖"）

**做法**：换一个**完全不同的 Python 安装**来跑 —— 不用 agent 环境的 3.11，用 `D:\PYTHON` 下的 3.13。

```
agent 环境   : Python 3.11.16
系统 Python  : Python 3.13.12      ← 另一个安装，装的东西完全不同
```

**结果**：✅ **直接跑通**，输出一模一样。

**结论**：模块**只用了标准库**（`sqlite3` / `sys` / `os`），没有第三方依赖 ——
换任何一台装了 Python 3.8+ 的机器都能跑，**不需要 `pip install` 任何东西**。

> 这正是契约 §3 定的"零第三方依赖"。如果当初用了 pandas，这一步就会变成"先装 50MB 的包，还可能版本不对"。

## 测试 2 · 换目录（目标目录里有 `logs/`）

**做法**：把 `call_log_v2.py` 拷到 `%TEMP%\repro_test\有logs目录\`，从那个目录运行。

**结果**：✅ 跑通，报表正常。

## 测试 3 · 换目录（目标目录里**没有** `logs/`）★ 暴露真 bug

**做法**：拷到一个**只有 .py 文件、没有 `logs/` 文件夹**的目录，直接运行。

**结果**：❌ 崩溃

```
File "...\call_log_v2.py", line 26, in connect
    return sqlite3.connect(DB)
sqlite3.OperationalError: unable to open database file
```

**根因**：`sqlite3.connect()` 会**自动创建数据库文件，但不会自动创建它所在的文件夹**。

**★ 为什么这个 bug 特别值得记**：

报错只说了 `unable to open database file` —— **一个"文件夹不存在"被报成了"文件打不开"**。
看到这句话，人的第一反应是查权限、查路径拼写、查磁盘满，**几乎想不到是少了个空目录**。

**现实后果**：别人把你的代码 clone 下来，**第一次跑就崩，而且不知道为什么**。

**修复**：在 `connect()` 里自己建目录。

```python
import os

def connect():
    os.makedirs("logs", exist_ok=True)   # 没有就建，有就当没看见
    return sqlite3.connect(DB)
```

**修复后重测**：✅ 跑通，`logs/` 自动创建出来。

## 测试 4 · 让别人跑（只看 README，不看代码）

**做法**：设想一个只看文档的人，能不能从零跑起来。

**结果**：❌ **目前做不到** —— 因为 **v2 还没有 README**。

**结论**：这正是 **D6 的任务**。README 至少要写清四件事：

1. 依赖（答案是：**没有**）
2. 怎么跑（`python week5\call_log_v2.py` / 加 `--report`）
3. 输入输出（往库里记调用记录 → 三张报表）
4. **它在整体项目里干什么**（手册点名必须写）
