## 二、四道题的实现思路（不给完整代码，给骨架和卡点）

### 题 1：单链表的 7 小问（★ 占分最多）

**共用结构**（这个可以直接写进"实验原理"）：

```cpp
typedef int ElemType;
typedef struct LNode {
    ElemType data;       // 存数据
    struct LNode *next;  // 指向下一个结点
} LNode, *LinkList;
```

**（1）随机生成 10 个不同的 3 位数（100~999），存进链表**

★ **"不同"是关键词** —— 必须去重。两个常规做法：

- 做法 A：生成一个，就到链表里查一遍，有就重生成（10 个数够用，简单）
- 做法 B：用一个 bool 数组 `used[1000]` 标记（更快，也更直观）

**头插还是尾插？** 报告要"输出链表内容"，题目没说顺序，两种都行。
但后面第 (3) 问要"输出位置"，**用尾插更符合直觉**（保持生成顺序）。

**（2）输出链表** —— 循环 `while (p) { printf("%d ", p->data); p = p->next; }`

**（3）查找，输出位置（首位置为 1）**

★ **位置从 1 开始，不是 0** —— 这是最容易写错的地方：
```cpp
int pos = 1;              // 不是 0
while (p && p->data != x) { p = p->next; pos++; }
if (p) printf("在第 %d 个位置", pos);
```

**（4）插入，要判断位置是否合理**

★ **合法范围是 `1 ~ n+1`**（n 是当前长度）：
- 插在第 1 个位置 = 插在表头前
- 插在第 n+1 个 = 追加到末尾
- 插在 n+2 = **不合法**

**两种写法**：
- 写法 A：找到第 `i-1` 个结点 `p`，然后 `q->next = p->next; p->next = q;`
- 写法 B（更简单，推荐）：**用"前驱指针"遍历**，`pre` 从 NULL 开始

**（5）按值删除**

★ 两个坑：
1. **必须找到"前一个"结点**（单链表删不了自己）
2. **删完要 `free()`**，否则内存泄漏

**（6）就地翻转（不占新空间）★ 这题最容易翻车**

**三指针法**，这是标准解法：

```
pre = NULL
while (p != NULL):
    next = p->next    ← ★ 先存下一个，再改 p->next
    p->next = pre     ← 反过来指
    pre = p
    p = next
头指针 = pre
```

★ **顺序不能反**：先 `p->next = pre` 再取 `p->next`，后面的结点就全丢了。
**这个错误你今天大概率会犯一次** —— 犯完记进"错误总结"，正好。

**（7）合并两个非递减链表 → 一个新的非递增链表，且不占新空间**

★ **关键在"非递增"** —— 用**头插法**：

```
两个链表 a、b 都已按非递减排好
结果从大到小 —— 所以每次挑【较大】的那个，头插进结果表
```

因为头插会把顺序倒过来：你从大到小挑、头插，结果就是**大的在前面**吗？不是——头插会把后来的放到前面，所以**从小到大挑 + 头插 = 从大到小**。

**推导一遍**（很重要，别背）：
```
从两个非递减表里，每次取【较小】的（也就是两个表头里小的那个）
头插进结果表
→ 取出的顺序：小 → 大
→ 头插后：大在前 → 结果是非递增 ✅
```

★ 要求"表中允许有重复数据" → 相等的时候也要取，别跳过。

### 题 2：链栈（入栈、出栈）+ **调试截图**

**结构**：
```cpp
typedef struct linknode {
    ElemType data;
    struct linknode *next;
} LiNode, *LiStack;      // 栈顶就是表头
```

**入栈 = 头插**，**出栈 = 删表头**。就这两句，比顺序栈简单。

### 题 3：链队列（入队、遍历、翻转）

**结构**（★ 队列要有"队头"和"队尾"两个指针，不然入队 O(n)）：
```cpp
typedef struct qnode {
    ElemType data;
    struct qnode *next;
} QNode;
typedef struct {
    QNode *front;   // 队头
    QNode *rear;    // 队尾
} LinkQueue;
```

- **入队**：`rear->next = q; rear = q;`
- **出队**：`p = front->next; front->next = p->next;`（★ 注意**带头结点**的写法，和不带头结点的写法不一样，课本用的是**带头结点**）
- **遍历**：从 `front->next` 开始走
- **翻转**：★ 最简单的方法是**先全部出队到一个链栈里，再全部出栈回来**（队列 + 栈的组合，正好复习前一题）

### 题 4：应用（1）（2）必做，（3）选做

#### （1）按基准值分割单链表（不占新空间）

★ **两种标准做法**：

- **做法 A（推荐，最容易写对）**：重建两个链表（小链表 + 大链表），最后接起来
  - 遍历原表，`< pivot` 的挂到 `small` 尾部，`>= pivot` 的挂到 `big` 尾部
  - 最后 `small尾->next = big头`
  - **没有新建结点**，只改了 `next` 指针 → 满足"不占新空间"

- 做法 B：就地双指针交换（容易写错，不推荐先在实验课上用）

★ 复杂度：一次遍历 O(n)，这就是题目说的"注意时间复杂度"。

#### （2）括号匹配（三种括号 + 非括号字符）

**用栈**。规则：
```
遇到 ( [ {  → 入栈
遇到 ) ] }  → 栈非空且栈顶是配对的左括号 → 出栈；否则 return false
其它字符    → 跳过（题目"增加对非括号字符的判断"就是这条）
扫完字符串 → 栈必须为空
```

★ 两个易错点：
1. **扫完了栈不空也是失败**（比如 `"((("`）
2. **栈空的时候遇到右括号也是失败**（比如 `")("`）

#### （3）迷宫最短路径（选做）

**BFS + 队列**：
- 队列里存坐标 `(x, y)`
- 每个格子记录"是从哪里来的"（前驱数组）
- 出队时把四个方向可走的格子入队并标记已访问
- 到 (8,8) 后，从终点按前驱回溯，就是最短路径

★ 关键：**BFS 保证第一次到达就是最短**（DFS 不保证）。

## 三、怎么在 VS Code 里调试（拿那个"栈顶截图"）

### ⚠️ 先说一个坑：这个项目在中文路径下，调试器读不了源码

我实测过：

```
gdb 在 E:\04_脚本与代码\...\seqlist.cpp 上：
   breakpoint 能打断点，但显示源码时警告
   "No such file or directory"  → 看不到代码行，截不了图

同样的文件复制到 C:\cppbuild\current.cpp：
   ✅ 完全正常，代码行、变量都能看
```

**原因**：gdb 打开源码文件时用的是 ANSI 编码，认不出中文路径。

**所以调试要在一个纯英文的副本上做。** 我已经配好了，你不用手动搞。

### 操作步骤

1. 在 VS Code 里打开你要调试的 `.cpp`（比如链栈那个文件）
2. 在**入栈函数的第一行**，行号左边点一下 → 出现**红点**（断点①）
3. 按 **F5**
   - 它会自动做三件事：把当前文件复制到 `C:\cppbuild\current.cpp` → 编译 → 启动调试
   - 第一次可能会弹"选择调试器"→ 选 **C++ (GDB/LLDB)**
4. 程序停在断点，**左边会出现 `current.cpp` 的副本**（调试就在这个副本里进行）
5. 按 **F10** → 执行下一行（单步跳过）
6. 左边 **"运行和调试"面板 → 变量** → 展开 `S`，能看到栈顶指针和 `S->data`
7. 停在你想要的状态时截图 —— **要拍到：代码行（有红点/箭头）+ 变量值**

> **截图技巧**：`Win + Shift + S` 框选，比手机拍照规范（老师明确要求**不要拍照**）。

### 如果 F5 起不来

按 `Ctrl+Shift+P` → 输入 `Debug: Select and Start Debugging` → 选 **"调试（ASCII 副本 + gdb）"**。

配置在 `.vscode\launch.json`，编译任务在 `.vscode\tasks.json`，这两个文件已经写好并验证过。
