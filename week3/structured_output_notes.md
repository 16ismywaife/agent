# D4 · 结构化输出（Agent 的地基）

> 实验时间：2026-10-09
> 模型：`deepseek-flash`（思考模式已关闭）
> 脚本：`week3/day1.py` → `d4_structured()`，命令 `python week3\day1.py --only 4`
> 对照实验脚本：`week3/_diag_d4_grid.py`（2×2 网格，每组 5 次）
> 数据：下面每个数字都是**实测输出**。

---

## 一、这一段要解决什么

**让模型的输出能被程序吃掉。**

听起来简单，但实测下来有**两种不同的失败方式**（见第三节），而且它们是两个独立的问题：

| 问题 | 谁解决 |
|---|---|
| 模型把 JSON 包在 markdown 代码块里 → `json.loads()` 报错 | **正则兜底**（方案二） |
| 模型返回的字段名/结构每次都不一样 | **`response_format` 管不了**，需要 schema 校验 |

> **为什么这段最重要**（手册 4.11 原文）：
> **Tool Calling 本质就是「让模型吐结构化输出」。**
> 模型不是直接执行函数，而是返回一个结构化的调用请求。**这一步学不会，Week4 的 Agent 会卡。**

---

## 二、两套方案

| 方案 | 做法 | 强度 |
|---|---|---|
| **一、硬约束** | `response_format={"type": "json_object"}` | **API 层保证**语法合法 |
| **二、正则兜底** | `re.search(r"\{.*\}", 文本, re.S)` + `json.loads` | 事后**清洗** |

**两者不是冗余，是"首选 + 降级"：**
方案一能用就用；模型不支持时（不是所有厂商都支持）降级到方案二。

### 本项目的实测输出（方案一）

```
reply:        {"姓名": "张小明", "科目": "数学", "分数": 88}
原始返回:      '{"姓名": "张小明", "科目": "数学", "分数": 88}'
兜底解析成功:  {'姓名': '张小明', '科目': '数学', '分数': 88}
completion_tokens: 19
```

**`原始返回` 用 `repr()` 打出来是关键验证** —— 单个 `'` 包着说明**没有代码块外壳**。
对比第三节里失败的样子：`'```json\n{...}\n```'`。

## 三、★ 2×2 对照实验：到底是「措辞」还是「约束」在起作用？

原始设计只对比"加不加 `response_format`"，但这会混入**措辞**这个变量。
所以拆成两组因素（每组各跑 5 次）：

|  | **软约束**（不加 `response_format`） | **硬约束**（加 `response_format`） |
|---|---|---|
| **明确措辞**（"只输出 JSON，不要任何其他文字"） | **5/5** 直接可解析 | **5/5** |
| **含糊措辞**（"用 JSON 格式给我"） | **1/5** ⚠️ | **5/5** |

### 结论 1：措辞明确时，软约束就够了

明确措辞 + 软约束 5 次输出**完全相同**，长度全是 35 字符：

```
{"姓名": "张小明", "科目": "数学", "分数": 88}
```

**加不加 `response_format` 结果一样。** 所以"软约束会失败"**只在措辞含糊时成立**。

### 结论 2：含糊措辞时，软约束的失败方式高度一致

含糊措辞 + 软约束，5 次里 4 次失败，**失败方式全是同一个**：

```
```json
{
  "姓名": "张小明",
  "数学": 88,
  "语文": 92
}
```
```

**★ 软约束最典型的失败不是"不输出 JSON"，而是"输出 JSON 但套了 markdown 代码块"。**

模型觉得自己答得挺好、格式也对，但 `json.loads()` 会直接报 `JSONDecodeError`。

**这就是方案二（正则兜底）存在的唯一理由** —— 把代码块和说明文字扒掉，只留花括号那段。

### 结论 3：正则兜底救得了"套壳"，救不了"没有"

| 输入 | 直接解析 | 正则兜底 |
|---|---|---|
| 纯 JSON | ✅ | ✅ |
| **JSON 套了代码块/说明文字** | ❌ | **✅ 救回来了** |
| 完全没有 JSON | ❌ | ❌ **救不了** |

最后一行只能靠**重试或改 prompt**。

## 四、★ 一个超出预期的发现：硬约束不管「schema」

看含糊措辞 + 硬约束那 5 次的输出：

```
{"name": "张小明", "数学": 88, "语文": 92}
{"name": "张小明", "scores": {"数学": 88, "语文": 92}}
{"name": "张小明", "scores": {"数学": 88, "语文": 92}}
{"type": "json_object", "name": "张小明", "scores": {...}}      ← 多了个字段
{"name": "张小明", "scores": {"数学": 88, "语文": 92}}
```

**5 次全部是"合法 JSON"（所以 `response_format` 的任务完成了），但：**

- 字段名是 `name`，不是我们要求的 `姓名`
- 结构是嵌套的 `scores: {数学, 语文}`，不是扁平的 `科目/分数`
- 还有一次多出一个 `"type": "json_object"` 字段

**所以：**

| 保证什么 | `response_format` 管吗 |
|---|---|
| 语法是合法 JSON | ✅ **管** |
| 字段名是你想要的 | ❌ **不管** |
| 结构是你给的形状 | ❌ **不管** |

**推论（直接影响 Week4）**：做 Agent 时，光靠 `response_format` 不够，
**还需要校验**（声明 schema，或解析后检查关键字段在不在）。
模型返回的 `tool_calls` 结构由 SDK/API 保证，但**工具的参数字典里有什么字段，仍要自己验**。

## 五、踩过的坑（这一段总共踩了 5 个）

> **★ 这 5 个全都不是 D4 的知识点，是脚手架和语法的问题。**
> 值得记下来，因为它们比 D4 本身更容易耗时间。

### 坑 1：`ask()` 加了必填参数，把 D1/D2/D3 一起弄坏

```
❌ ask(client, model, messages)          -> TypeError: missing 1 required argument
```
给新参数**加默认值**（或改用 `**kw`）就没事。

### 坑 2：位置参数 vs 关键字参数

```python
def ask(client, model, messages, **kw):    # **kw 只收【关键字】参数
ask(client, model, prompt, format)         # ❌ 第 4 个是位置参数
ask(client, model, prompt, response_format={"type":"json_object"})   # ✅
```
```
TypeError: ask() takes 3 positional arguments but 4 were given
```

### 坑 3：SDK 的参数名是 `response_format`，不是 `format`

`completion()` 会把 `**kw` 原样传给 SDK，所以名字必须用 SDK 认的那个。
（顺带：`format` 还是 Python 内置函数的名字，拿来当变量名会盖住它。）

### 坑 4：★ 变量加了引号 → 变成字符串字面量

```python
[{"role":"user","content":"prompt"}]     # ❌ 发出去的是 "prompt" 这四个字母
[{"role":"user","content":prompt}]       # ✅
```

**报错完全看不懂**：
```
400 - Prompt must contain the word 'json' in some form to use 'response_format'
```

**原因**：模型收到的正文就是 `prompt` 这四个字母，里面当然没有 "json"。
**从 API 的角度它没错** —— 那确实是一条合法的消息，只是内容很奇怪。

> **★ 这个坑 Week1 已经踩过一次了**（手册 6.1 节）：
> `fig.savefig("out_path")` → 存成怪名字，因为**变量加引号变成字面字符串**。
> **同一个根因，换了地方又踩一次。**
>
> **排查口诀**：报错说"你没给 X"时，**先确认 X 实际发出去的是什么**，
> 而不是检查你写的 X 对不对。做法就一行：`print(repr(X))` ——
> **`repr()` 会显示引号，普通 `print()` 不会。**

### 坑 5：兜底代码放进了 `except` 块里

```python
    try:
        txt = ask(...)
    except Exception as e:
        m = re.search(...)        # ❌ 只有【报错时】才跑
```

**这次没报错**（硬约束成功了），所以 `except` 里的兜底逻辑一次都没执行 ——
**表现是"改了代码但输出和上次一模一样"**。

**正确结构**：兜底要对"最终拿到的东西"做清洗，所以放在 `try/except` **外面**：

```python
    txt = None                    # ← 预初始化，防止 except 触发时 txt 不存在
    try:
        txt = ask(...)
    except Exception as e:
        print("不支持 response_format：", e)

    print("原始返回:", repr(txt))                      # 缩进和 try 同级 = 一定会执行
    m = re.search(r"\{.*\}", txt or "", re.S)         # txt or "" 防止 None
    ...
```

**判断口诀：想让某段代码"不管成功失败都执行"，它的缩进必须和 `try` 一样。**

## 六、已知局限

1. **只测了一个模型**（`deepseek-flash`）。"明确措辞时软约束就够"**未必适用于别的模型**
2. **每组只有 5 次**。方向明确（1/5 vs 5/5），但具体比例不必当真
3. **只测了一个抽取任务**。换任务类型（分类、生成）结论可能不同
4. **没测 schema 校验方案**（比如 JSON Schema / Pydantic）。第四节那个问题只发现了，没解决
5. **没测"完全没有 JSON"时的重试策略**
