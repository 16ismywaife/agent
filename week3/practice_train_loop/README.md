## 先纠正一个概念（这可能就是你记不住的原因）

手册里把**两样东西**都叫「训练循环」，你脑子里这两个概念在打架：

| 叫法 | 是什么 | 代码 |
|---|---|---|
| **外层循环** | 「过几遍」 | `for epoch in range(3):` |
| **内层 5 步** | 「一批数据怎么学」 | `zero_grad → ... → step` |

**你要背的 5 步，是内层，而且它处理的是「一批（batch）」不是「一轮（epoch）」。**

完整结构是 **4 层套嵌**，5 步只占最里面一层：

```
第 1 层  for epoch in range(3):          过几遍
第 2 层      model.train()                切回训练模式
第 3 层      for x, y in train_ld:       一批一批地取（MNIST 是 938 批/轮）
第 4 层          optimizer.zero_grad()    ← 你背的 5 步在这里
                 out = model(x)
                 loss = criterion(out, y)
                 loss.backward()
                 optimizer.step()
             acc = evaluate()             这轮学得咋样
```

**只背第 4 层，却要拿它拼整台机器 —— 所以一紧张就乱。** 把 4 层一起记，反而简单。

## 练习二：故意写坏（`breakdown.py`）

**这个练习才是关键。**

```powershell
cd E:\agent\week3\practice_train_loop
python breakdown.py
```

它会拿 `train.py`，**自动逐个破坏关键行**，每种破坏都真跑一遍训练，然后给你一张对照表。

**实测结果（跑出来的，不是我编的）：**

| 破坏方式 | 你预期会怎样 | 实际会怎样 |
|---|---|---|
| 去掉 `optimizer.zero_grad()` | 梯度累加 | **首轮末梯度范数 30.78（基线的 14.5 倍）**，精度 0.2780 → **0.1520** |
| 去掉 `out = model(x)` | 崩 | ✅ 崩：`NameError: name 'out' is not defined` |
| 去掉 `loss = criterion(out, y)` | 崩 | ✅ 崩：`NameError: name 'loss' is not defined` |
| 去掉 `loss.backward()` | 不崩 | ✅ **不崩，梯度恒为 0.00**，精度卡在 0.0990（随机） |
| 去掉 `optimizer.step()` | 不崩 | ✅ **不崩，梯度正常 2.19**，精度卡在 0.0990（随机） |
| 把 `zero_grad` 挪到 `step` 之后 | 精度下降 | ⚠️ **精度一点没变（0.2780）** —— 见报告里的解释 |
| 评估不写 `model.eval()`（有 Dropout） | 精度被压低 | ✅ 0.2780 → **0.2600** |
| 评估不写 `torch.no_grad()` | 精度不变 | ✅ **完全不变**，只是慢、费显存 |

**为什么这个方法有效**：你记住「要写 zero_grad」是因为被告知要写；你记住「不写它会怎样」是因为**你亲眼见过它错**。后者不会忘。

**三个反直觉的发现**（报告里有详细解释，这几个比口诀值钱）：

1. **`zero_grad` 的累积效应在「第一步」根本看不出来** —— 因为第一步之前没有「上一轮」可累加。所以**不要用「跑一个 batch」判断训练循环对不对**。
2. **把 `zero_grad` 挪到 `step` 之后，精度可能一点不变** —— 它等价于「把学习率乘 2」，而这个模型学习率本来就保守。**「没报错、精度还行」不等于代码对。**
3. **漏掉 `backward()` 或 `step()` 不会报错** —— 代码正常跑完、正常打印，只是精度永远停在随机。**这类不报错的 bug 最危险**，也正是为什么每轮都要 `evaluate()` 盯着看。
