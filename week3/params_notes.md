## 一、`temperature`：随机性

### 实测（每个值连发 4 次，同一问题）

| `temperature` | 不同输出数 | 例子 |
|---|---|---|
| **0** | **1 种** | 做一个"AI 帮小商家自动回复差评"的工具，按月收费。 |
| **0.7** | **3 种** | 同一个点子，但表述有变化 |
| **1.5** | **4 种** | 为"一人食"餐厅提供"拼桌社交"小程序…（完全不同） |

**梯度符合预期**：0 完全固定 → 0.7 有变化 → 1.5 每次都不同。

### ★ 补充验证：`temperature=0` 到底有多"确定"

**起因**：D3 的记录里写过「`temperature=0` 时输出仍可能不同（3 种）」，
但 D5 两次跑都是「1 种」，**两种说法对不上，所以专门查了一次**（n=10）：

| `temperature` | 连发 10 次 | 不同输出 | 空字符串 |
|---|---|---|---|
| **0** | 全部相同 | **1 种** | 0 |
| 1.5 | 几乎全不同 | **10 种** | 0 |

```
temperature=0  10 次全是：做一个"AI 帮小商家自动回复差评"的工具，按月收费。
```

### ★ 结论 + 对 D3 记录的修正

**修正后的说法：**

> **在这个模型（`deepseek-flash`）上，`temperature=0` 高度确定** ——
> 10 次输出逐字相同。

**D3 那条「`temperature=0` 仍可能不同」是不可靠的**，原因是**那次的测量方法有缺陷**：

- D3 那次用了 `max_tokens=60`（太小），正文很可能被截断或有空字符串
- 于是"3 种不同输出"是**截断产物**，不是真实的温度差异

> **★ 这与 D1 踩的坑是同一个**：
> **「三次都一样」和「三次都是空的」在代码里长得一模一样。**
> **测量方法的缺陷会直接变成错误结论** —— 这已经是第三次遇到同类问题了
> （① D1 的 `max_tokens=60`、② D5 我最初版本、③ D3 这条记录）。

**但要注意适用范围**：只测了一个模型、一个问题。
**换模型/厂商不保证绝对一致**，所以实践建议不变：

| 场景 | 建议 |
|---|---|
| 要 JSON、要结构化、要可复现 | `temperature=0` |
| 日常对话、要一点变化 | `temperature=0.7` |
| 创意写作 | `temperature=1.5` |

## 二、`max_tokens`：输出长度上限

### 实测（同一问题「用三句话介绍什么是机器学习」）

| `max_tokens` | 正文字符数 | `finish_reason` | 判读 |
|---|---|---|---|
| **50** | **88** | **`length`** | 话说到一半被砍断 |
| 100 | 112 | `stop` | 正常说完 |
| 500 | 116 | `stop` | 正常说完（上限用不到） |

**★ 关键观察：`max_tokens=50` 时正文有 88 个字符，但 `finish_reason=length`。**

**说明它不是"没生成内容"，而是"内容不完整"。**
**光看 `content` 你分不出这两者** —— 所以必须看 `finish_reason`。

### 为什么这一栏在 D1 那次更极端

D1 跑 `--all` 时（**思考模式开着**），`max_tokens=100` 得到的是**空字符串**：

| 条件 | `max_tokens` | 正文 |
|---|---|---|
| 思考**开** | 100 | **0 字符**（100 token 全被思考吃掉） |
| 思考**关** | 50 | 88 字符（被截断，但有内容） |
| 思考**关** | 100 | 112 字符（完整） |

**同一个参数，因为"思考模式"这个变量的不同，表现完全不一样。**
→ 所以 D1 那次的教训是：**`max_tokens` 要连同思考模式一起看，不能单独判断。**

## 三、`finish_reason` 是什么

**一句话：模型"为什么停下来"的标记。**

```python
r.choices[0].finish_reason      # ★ 和 .message 平级，不在 .message 里面
```

| 值 | 意思 | 该怎么办 |
|---|---|---|
| **`stop`** | 正常说完了 | ✅ |
| **`length`** | 撞到 `max_tokens` 上限被截断 | 内容不完整 → 调大 `max_tokens` |
| **`tool_calls`** | **模型要调工具，说话中止** | ★ **Week4 的 Agent 靠它判断** |
| `content_filter` | 被安全策略拦了 | 换说法 |

**`content` 和 `finish_reason` 是两件独立的事：**

```
content       = 说了什么
finish_reason = 为什么停下
```

**这个字段在 Week3 是"检查有没有被截断"，到 Week4 会变成"控制程序走哪条路"：**

```python
# Week4 Agent 主循环的核心判断（手册 4.11）
if not msg.tool_calls:      # 没有工具请求 → 说明它要直接回答
    return msg.content
# 否则 → 执行工具，把结果发回去，继续循环
```

## 四、这一段的实用结论

| 要什么 | 怎么设 |
|---|---|
| 结构化输出（JSON）要稳定 | `temperature=0` |
| 不能让回答太长 | 设 `max_tokens`，**但要检查 `finish_reason` 确认没被截断** |
| 判断"回答是否完整" | **看 `finish_reason`，不能只看 `content`** |
| 省钱 | 关掉思考模式 + 给合适的 `max_tokens`（给太少会拿到废内容，反而更亏） |

## 五、已知局限

1. **`temperature=0` 的确定性只测了一个模型、一个问题**（n=10）。换模型未知
2. **`max_tokens` 的实测基于"思考关闭"**。思考开着时数值完全不同（见第二节）
3. **没测 `top_p`**（手册提到"一般只调 `temperature` 就够"）
4. **没测 `temperature` 中间值**（如 0.2 / 0.5）的细腻变化
5. **没测并发/长对话下的表现**
