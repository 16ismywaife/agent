## 10-05（Week2 · MNIST 训练循环 + 保存/加载模型）★ 本周交付物

- **做了**：`LOOP.py` 全量训练 3 个 epoch → **准确率 97.36%**（RTX 5060，60000 张，110 秒）；`torch.save(state_dict)` 存模型 → `loadtest.py` 加载推理，`pred: 7, label: 7` 一致
- **卡了**：`loadtest.py` 报 `RuntimeError: a Tensor with 784 elements cannot be converted to Scalar`
- **根因**：**括号位置错了**。我写的是
  ```python
  pred = model(x.unsqueeze(0).argmax(dim=1).item())   # ❌ 全在 model() 里面
  ```
  `argmax` 跑在**输入图像**上（在 784 个像素里找最大值），而不是在**模型输出**上。所以 `model()` 收到了一个数字，`item()` 又想把 784 个元素的张量变成标量
- **解了**：
  ```python
  pred = model(x.unsqueeze(0)).argmax(dim=1).item()   # ✅ argmax 在外面，对输出做
  ```
- **★ 学到**：**`model(x)` 的右括号在哪结束，决定了后面所有操作作用在谁身上。** 拆成两行就不会错：
  ```python
  out  = model(x.unsqueeze(0))     # 先拿输出（形状 [1, 10]）
  pred = out.argmax(dim=1).item()  # 再在输出上取类别
  ```
- **记一下**：`state_dict()` **只存参数不存结构**，所以加载时 `Net` 类必须和训练时一模一样，先建结构再灌参数

## 10-05（Week3 · D2 Prompt 对比实验）

- **做了**：同一句话对比「有没有 system」，每组各跑 5 次 → `week3/prompt_compare.md`
- **卡了 1**：只跑 1 次就下结论，得出「system 帮倒忙」，**加到 5 次才推翻**
- **解了 1**：**n≥5 看分布，不看单条。** 样本太少时，随机性会被当成变量的效果
- **卡了 2**：标签印错位了（把"有 system"和"无 system"标反）
- **解了 2**：靠 **`prompt_tokens` 分辨** —— 带 system 那次多出 26 个 token。**这两个值不一样，就是标签错了的硬证据**
- **★ 结论（和网上教程相反）**：**system 的作用是「定义输出契约」，不是设定人设。**
  决定性的半句是「只输出改写后的句子」；身份（技术文档编辑）影响最小。
  | 指标 | 无 system | 有 system |
  |---|---|---|
  | 字数范围 | 14 ~ **477** | 18 ~ 30 |
  | 变异系数 CV | **1.83** | **0.22** |
  | 给了"菜单"（多选项+解释） | 1 / 5 | 0 / 5 |
- **记一下**：**一致性比单条质量重要**。无 system 时单条可能更好，但输出长度从 14 到 477 字乱跳，**下游代码没法写**。这和 D4 结构化输出是同一件事

- **卡了 1**：模型回复的 `role` 写成 `system`（应为 `assistant`），**不报错、答案还是对的**
- **解了 1**：`role` 决定"这句话是谁说的"。写成 `system` 等于把模型的输出变成"给模型的命令"。
  **★ 抓手：一个对话里应该有且仅有 1 个 `system`。**

- **★ 验证方式（比"看答案对不对"硬）**：`prompt_tokens` 的算术关系
  ```
  轮1 total 112 -> 轮2 prompt 120   差 +8  ← 正好是新问题的 token 数
  轮2 total 182 -> 轮3 prompt 190   差 +8
  ```
  **下一轮 prompt = 上一轮完整内容 + 新问题**，没多没少 —— 这就是历史结构正确的数学证明
- **顺手验证了「输出契约」**：system 里加「每次回答控制在 3 句话以内」
  | | 无约束 | 有约束 |
  |---|---|---|
  | `completion_tokens` | 899 / 1496 / 1172 | 86 / 65 / 61（**−94%**） |
  | 末轮 `prompt_tokens` | 2426 | 192（**−92%**） |
  **★ 但要分清两种效果**：第 1 轮输入几乎相同，`899→86` 是**契约的直接效力**；
  第 2/3 轮主要是**连锁效应**（回复短 → 历史短 → 越滚越省）。
  **结论：输出契约不只省当次的钱，还省后面每一次的钱**
- **记一下**：`history` 每轮涨 2 条（`1 + 2N`），**而每次请求都要把整个 history 发出去** —— 这就是"上下文管理"问题的来源。Week4 的 Agent 涨得更快（每调一次工具多两条）
